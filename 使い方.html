楽曲情報DBエディタ

ゆかりスターのエクスポートファイル（.ylexa）に含まれるSQLiteデータベースを、画面上またはExcelで編集するためのツールです。

保存: ［上書き保存］では現在開いているファイルへ保存し、［名前を付けて保存］では別名で保存できます。

基本的な使い方

  1. ［開く］で .ylexa を選択します。
  2. 曲、人物、タイアップ、タグ、各関連データなどのタブを開きます。
  3. ［追加］［編集］［有効化／無効化］［削除］でデータを変更します。
  4. ［上書き保存］または［名前を付けて保存］で編集内容を保存します。

画面上での編集

Excelと同じ分類でタブが分かれています。各タブには検索、追加、編集、有効化／無効化、完全削除があります。

IDの自動採番

曲・人物・タイアップ・タグ・メーカー・別名データを追加すると、現在のDB内にある同じ接頭辞の最大番号へ1を加えたIDが自動生成されます。

設定した接頭文字が MyName の場合: MyName_P_120 が最大 → 次の人物IDは MyName_P_121

歌手関連などの関連表では、曲IDを入力すると、その曲で使用中の最大sequence番号＋1が自動設定されます。

有効化／無効化と削除について

［有効化／無効化］は、選択行の無効値を0と1で切り替えます。無効行はツールとExcelでグレー表示され、有効に戻すとグレー表示が解除されます。

［削除］はDBから完全に消す危険な操作です。赤文字の警告画面で確認チェックを入れない限り削除ボタンは押せません。Deleteキーには削除操作を割り当てていません。

Excel編集

［Excel書き出し］で現在のDBを出力し、編集後に［Excel取り込み］で反映できます。［新規入力テンプレート］では空の入力ブックを作成します。

青色の列: 入力・編集する列
緑色の列: IDから名称を自動表示する確認用列

確認用列には数式が設定されています。例えば歌手関連シートで曲IDと人物IDを入力すると、右側に曲名と人物名が表示されます。表示名は参照先シートへのリンクにもなっています。

Excelで守ること

  • シート名を変更しない。
  • 1行目と非表示の2行目を変更しない。
  • 既存行の主キーIDを変更しない。
  • 確認用の緑列を直接入力しない。
  • 無効列は0または1で入力する。1の行は自動的にグレー表示される。

データ構造と安全性

.ylexa はZIP形式で、内部に ExportMusicInfo.sqlite3 が入っています。本ツールは作業用フォルダへ展開して編集し、保存時にSQLite整合性とZIP整合性を確認します。

人物名は歌手・作詞・作曲・編曲で共有されます。同じ人物を複数曲へ紐付ける場合は、人物マスターを重複登録せず、関連表から同じ人物IDを参照してください。

一括追加の複数値区切り: 歌手・作詞・作曲・編曲・タグ・シリーズなどを1セルに複数入力する場合は、一括追加画面で指定した区切り文字だけを使用します。初期値は半角セミコロン ; です。名称自体に含まれる文字で誤分割しないよう、指定文字以外は区切りとして扱いません。

独自拡張テーブルとゆかりスター互換出力

.kvbd では独自追加テーブルを保持できます。 .ylexa へ保存する場合も追加テーブルは削除されず、そのままファイルに含まれます。

注意

独自追加テーブルを含む .ylexa をゆかりスターで読み込み、 ゆかりスター側から再エクスポートすると、 ゆかりスターが認識しない独自テーブルは失われます。

人物の別名義・グループ所属

.ylexaを開いた場合は独自テーブルを自動追加せず、「別名義」タブからKVDB形式へ変換した時点で追加します。

「別名義」タブでは、人物同士の関係を独自拡張テーブル kvdb_person_relation に登録できます。

  • 別名義：同一人物の別名義を関連付けます。
  • 所属グループ（メンバー）：人物と所属グループ・バンドを関連付けます。所属情報は1件だけ保存され、グループ側では所属メンバーとして自動的に逆引き表示されます。

例：影山ヒロノブ → KAGE（別名義）、影山ヒロノブ → JAM Project（グループ所属）

データの複製

一覧で1件を選択し「複製して新規追加」を実行すると、複製専用画面が開きます。

  • 各項目の「複製元と同じ」にチェックすると、その項目を複製元からコピーします。
  • 曲のタグは「複製元と同じ」が初期状態でONになり、複製元のタグを引き継ぎます。必要に応じてチェックを外して編集できます。
  • 曲では歌手・作詞・作曲・編曲も個別に複製できます。
  • 複製元とタグを含む内容が完全に同じ場合は保存できません。タイトル、タグ、その他のいずれかが異なれば保存できます。

別名義の一括追加

［一括追加］で登録対象を「別名義」にすると、人物関係をCSV/TSVでまとめて登録できます。

列は「人物（メンバー）」「別名義・所属グループ」「種類」「無効」です。 人物名が既に人物DBにあれば既存IDを使用し、存在しない場合は人物を自動で新規登録します。

キーボードで素早く入力する

追加・編集画面とタグパネルでは、Tabキーで編集可能な入力欄を上から順に移動し、 最後に［保存］ボタンへ到達します。保存の次は先頭の入力欄へ戻ります。 ID欄を含め、画面上の項目を上から順番にTabキーで移動し、最後に［保存］ボタンへ到達します。保存の次は一番上のID欄へ戻ります。

  • Tab：次の入力欄へ
  • Shift + Tab：前の入力欄へ
  • Ctrl + PageUp：前のメインタブへ
  • Ctrl + PageDown：次のメインタブへ
  • Ctrl + S：保存

人物関係の編集

人物の［追加］または［編集］画面では、基本情報に加えて 「別名義」「所属グループ」「所属メンバー」を直接編集できます。 左側のタグパネルから編集した場合と同じ人物関係テーブルへ保存されます。

DBファイルをドラッグ＆ドロップで開く

起動直後などDBをまだ開いていない状態では、.kvbd または .ylexa をメイン画面へドラッグ＆ドロップして開けます。 対応していないファイルは無視されます。

Excelで既存データをまとめて更新する

既存DBをExcelへ書き出して編集し、再取り込みするとIDごとに比較します。 ふりがな・日付・カテゴリなどはツールと同じ保存形式へ正規化してから比較し、 正規化後に差分が無い行はDBへUPDATEしません。

不正な日付、カタカナとして扱えないふりがな、存在しない参照IDなどは エラーとしてスキップされます。既存IDのエラーはエラー一覧から該当レコードを 個別編集画面で開いて修正できます。

Excel取込時のふりがな正規化

Excelから取り込むふりがなは、DBへ反映する前に通常編集と同じ保存形式へ正規化します。 ひらがなはカタカナへ変換し、「～」「〜」は長音記号「ー」へ変換します。 それでも残る非カタカナ文字は除去し、その結果から検索用ふりがなも再生成します。 差分判定は正規化後の値で行うため、正規化後に既存DBと同じ値になる行は更新しません。

タグパネルの左右配置

タグパネル右上の「≡」から「左側に表示」「右側に表示」を選択できます。 初期状態は左側です。変更した配置は設定へ保存され、次回起動時にも同じ側へ表示されます。 「×」では従来どおりタグパネルを非表示にできます。

タイアップ名からシリーズを作成

タイアップの一括書き込み画面で「タイアップ名から新規」を使用すると、 選択したタイアップの名称をシリーズ名へ、タイアップよみをシリーズよみへ引き継ぎます。 元のタイアップよみが空欄の場合は、シリーズよみも空欄で開始します。

複数関連項目の並び順

曲の歌手・作詞・作曲・編曲・タグ、およびタイアップのシリーズは、選択済みチップの「↑」「↓」で順番を変更できます。保存した順番はDBのsequence値（0,1,2...）として保持され、再読込時も同じ順序で表示されます。

カテゴリ細分類（KVDB独自機能）

既存カテゴリは大分類としてそのまま使用し、その下へKVDB独自の細分類を追加できます。 例: 「001 アニメ」→「001 TV」「002 OVA」「003 劇場」。 上位細分類も指定できるため、必要に応じてさらに階層化できます。

タイアップ編集画面とタグパネルから細分類を紐づけます。 大分類と一致しない細分類は保存できません。

タグから複製曲のキーワードを設定

［ツール］→［設定］で 「曲の複製時、キーワードが未変更ならタグ名で区別する」 を有効にできます。初期状態はオフです。

ゆかりスター互換DBで有効です。曲キーワードが空欄の場合はタグ名を設定し、 キーワードが複製元と同じ場合は元キーワードの後ろへタグ名を追加します。 KVDBではこの自動コピーは行いません。

KVDBの同名曲判定

KVDB形式では、曲名が同じでも歌手・タイアップ・作詞・作曲・編曲・タグなど 他の情報で区別できる場合は、曲キーワードを入力しなくても別曲として登録できます。

ID以外の曲情報が既存曲とすべて同じ場合だけ登録を止め、 区別できるキーワードの入力を求めます。 ゆかりスター互換形式では従来どおり、同じ名称を登録するときは キーワードで区別する方式を使用します。

「曲の複製時、キーワードが未変更ならタグ名で区別する」設定は ゆかりスター互換DBでのみ動作し、KVDBでは使用しません。

一括書き込みで空欄に置換

一括書き込みでは、入力欄が空欄でも「すべて上書き」または 「置換」を選択すると、現在登録されている値を空欄へ置き換えます。 歌手・作詞・作曲・編曲・タグ・シリーズなどの複数関連項目は、 空欄で「置換」すると現在の紐づけをすべて解除します。

空欄の上書き／置換をプレビューへ反映するときは確認警告を表示します。 キャンセルした場合は変更しません。

一括書き込みの指定タグ置換

曲の一括書き込み画面では［指定タグ置換...］から、 置換元タグと置換先タグを指定できます。 対象曲に付いている置換元タグだけを差し替え、 その他のタグと並び順は維持します。

置換元タグが付いていない曲はスキップします。 置換先タグが既に付いている場合は二重登録せず1件に整理します。 通常の一括書き込みと同様に、まずプレビューへ反映してから ［決定］でDBへ書き込みます。
